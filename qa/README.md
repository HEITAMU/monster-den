### 完整入口检查如何运行

测试加载未经改写的 `GameMain.ts`、玩法核心、平台适配和模型库代码，以及实际 `Boot.scene` 和两份模型 JSON。TypeScript 仅转换为可在测试宿主执行的 CommonJS。宿主提供 JSDOM 和 Canvas 2D 环境，图形后端是官方 Cocos 3.8.8 的 **EmptyDevice**。

五房通关使用测试手册中的固定 21 发路线，每次发射都通过 DOM 鼠标事件、Cocos 输入分发和 GameMain 拖拽逻辑，所有拖拽力度至少为 11%。房间切换通过实际工具卡回调完成；没有将玩家传送到出口，也没有直接写入胜利状态。每个房间结束时仍有存活敌人。

3298 是固定步进执行的引擎帧数，**不代表测得了手机帧率或加载性能**。测试证明这条确定路线能够通过当前集成代码，不证明新玩家手感、长期耐玩程度或关卡平衡已达到发行标准。

### 资源与恢复边界

- 检查中累计初始化了 296 个运行时 Mesh。场景销毁后，记录中未调用销毁生命周期的 Mesh 数为 0。计数包装器仍执行引擎原来的 `initialize` 和 `destroy`；这验证资源所有权与释放调用，尚未测量真实 GPU 显存回收量。
- 广告 ID 未配置、网页测试广告未启用时，点击奖励入口不增加金币，也不触发救援，暂停状态能恢复。
- 使用明确标记为 `source: "test"` 的旧局凭证，验证当前钱包与快照不变，旧凭证不会被标记为已应用。这是适配逻辑测试，没有实际播放广告。
- 已结算胜利可以重新打开，基础收益不会再次发放；未结算失败可以重新打开结算与救援选择。
- 对合法存档外壳注入损坏的内层游戏快照后，旧快照被清理，回到首页并可以开始新局；不会将存档错误误报成模型加载失败。JSON 中的一条 `expectedWarnings` 是这个刻意构造的错误恢复场景所预期的警告。
- 保存与恢复使用测试宿主的网页 `localStorage`，并检查了前后台事件和组件销毁。失败终局与错误恢复的额外分支使用了明确的测试数据，不属于 21 发自然通关路线。

## 尚未由这些报告验证

**EmptyDevice 不产生真实 WebGL 像素。** 因而本目录的两份通过报告不能声称以下项目已通过：

- WebGL1/WebGL2 着色器在真实驱动上的编译、UBO 和采样器绑定、透明混合、文字纹理，以及最终画面质量。
- 手机上的帧时间、触摸手感、DPR 与安全区域适配、内存峰值、发热和长时间连续游玩。
- 真实可听见的音效、音乐、设备音量与微信前后台音频表现。
- Cocos Creator 3.8.8 编辑器对 `.effect` 等资产的导入，以及正式微信平台构建、包体预算和微信真机运行。
- 真实微信广告账号资格、广告填充、完整观看回调、收入或上架审核结果。

源码层的 shader 核查确认当前游戏所用的 global/local UBO、材质块、顶点颜色及 Label/Graphics 属性与 3.8.8 的布局一致；这仍不能替代 GPU 编译与截图检查。

## 复现

提供官方 `cocos-engine` 3.8.8 源码目录及其可用构建依赖后运行：

```sh
COCOS_ENGINE_SOURCE=/path/to/cocos-engine node tools/check-types.cjs
COCOS_ENGINE_SOURCE=/path/to/cocos-engine node tools/check-game-headless.cjs
COCOS_ENGINE_SOURCE=/path/to/cocos-engine npm run build:web
```

EmptyDevice 检查需要可用的 `@cocos/ccbuild`、`typescript`、`jsdom` 和 `@napi-rs/canvas`。脚本使用已有安装，不会自行下载依赖或改写官方引擎源码。

真实浏览器检查脚本已经提供，需要能够启动 Chromium 的环境：

```sh
npm run check:web -- https://your-preview.example/
```

不传 URL 时，脚本服务本地 `web/`。它会检查实际 WebGL 后端、绘制统计、控制台与请求错误，执行首页按钮和首次拖拽发射，并输出四张截图。结果写入 `.build/game-browser/`。当前执行器的 Chromium 曾在启动时遇到套接字权限限制；在新的真实浏览器结果产生前，不把这个脚本的存在当作测试通过。
