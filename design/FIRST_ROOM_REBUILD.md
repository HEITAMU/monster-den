# 0.4.0-alpha 首房连锁机关与操作验收

本工作分支不是已通过的商业游戏、美术终稿或微信包；它用于验证已批准设计的第一分钟能否产生“不同打法、场景因果、立即反馈”。

## 实现目标

- **两种可玩的第一房解法**：中央木栏仍可直接冲撞。另一条路线需要玩家向左侧撞第一枚活体菌核，引发五枚菌核依次延时引爆，震碎木栏，伤害前方守卫。拿主宝物再进出口仍是唯一通关条件。
- **物理与表现同一信号**：每个菌核具有碰撞触发半径、0.12秒首发引信、邻居距离触发、延时爆发、木板破坏、守卫受击与轨道柜子推动代码。客户端只根据服务端无关的确定性模型事件播放提示、冲击环和三维粒子，不通过 UI 假改场景。
- **三维区别**：现有 Blender 蘑菇模型作为下半身，另加特殊雕刻形态的多瓣菌冠（顶点颜色与发光效果），地面孢子环，启动时脉冲与击中后熄灭。它仍是阶段性资产，不代表最终角色、场景、美术或音效标准。
- **方向与冲撞**：保留当前固定摇杆以及严格从其坐标推导发射，补充真实 WebGL 输入测试：向上推必须指向房间北方，小兽动画朝北；直线原路线不得误触侧边菌核。
- **存档与连锁**：引信状态、连锁层数和是否消耗进入快照；旧房间快照不会凭空补刷菌核；非法状态恢复拒绝且不修改已有世界。

## 验收条件

1. Node/TypeScript 核心逻辑测试通过，原直线全五房路线不变；另有一发触发五枚菌核、木板被毁、守卫受伤、主宝物仍待拾取的确定性断言。
2. 30/60 帧输入与保存/恢复在引信进行时继续一致，近距离预览只停在交互点，没有把后续连锁位置伪装成精确可预测落点。
3. Chromium 实际 WebGL 运行并截图：首房未触发与触发后；完整旧主线、可选钱袋和触摸取消回归均通过。
4. 实际观测记录关联准确运行提交。未完成 Creator 3.8.8 编辑器导入、微信开发者工具与真机前，不能宣传微信上架或手机帧率已达标。

## 当前技术取舍

首关采用纯脚本描述并按距离传播的固定菌核簇，目的是测试物理互动是否足以激发探索。还没有随机房间生成或长线成长。若该机制的玩家测试不产生明显乐趣，下一步应重看撞击与风险收益，而不是无脑增加菌核数量。
