详细批准内容见 [APPROVED_SCOPE.md](APPROVED_SCOPE.md)。核心为竖屏、固定斜俯视的真实三维场景。本轮将输入改为底部固定摇杆同向推动、松手冲撞；移动、击退、破板、推柜、取宝共用这套操作。每房拿到宝物再到出口即可离开，**不要求清光敌人**。柜子的位置改变要持续影响后续通路和挡箭效果，敌人的下一次攻击方向提前显示。

已批准的第一段是一个场景主题、一名小兽、三类敌人行为、三件改变操作的工具、四间普通房和一间终点房，包含成功、失败、重进、结算和可选广告入口。当前三种基本行为是短距离守卫追撞、弩手发箭和长距离冲锋；窝主沿用更强的冲锋行为，并非已完成多阶段 Boss 系统。

角色和主要环境不得退回静态图片平移、简易线条或基础几何样机。可编辑模型、动作与实机显示都需要检查。所谓“2030 仍不过时”是追求长期玩法价值的目标，不是兼容性、留存、收入或未来画质的保证。

| 主观音频品质 | 原创谱面、实际音频、响度和循环边界测量已具备；是否悦耳、外放是否清楚、配乐是否疲劳及是否达到用户期待，需要完整听审与手机反馈。不能以测试通过宣称“顶级”。 |
| 长期耐玩与收入 | 当前仍是五间固定手工房，局外仅基础金币和开局工具解锁。尚无真实玩家留存或商业数据，不能保证长期可玩、复利或赚钱。 |

## 5. 下一步优先级

1. **先完成这一候选的实际 WebGL 验收与留档。** 对齐网页版本、被测提交及资源哈希，检查固定摇杆、五房路线、新角色/环境、首页大号展示、保存恢复与音频。把新报告和截图存入 `qa/`，再给本轮总结果；不沿用 0.1.1 的通过状态。
2. **取得真实新玩家的首局反馈。** 使用清洁独立存档，让玩家自然操作，不提前讲最佳路线。按 [PLAYTEST.md](PLAYTEST.md) 记录是否找到摇杆、能否理解同向推动和推距力度、是否误在场景起手、能否回中取消，以及目标与出口理解、受伤原因和右侧工具使用。观察何时开始觉得拖沓或无聊，再判断当前提示、节奏和画面是否有效。
3. **同时做手机性能与音频验证。** 分别检查首次/缓存加载、八方向摇杆、第二触点、取消、工具点击、前后台、连续五房、结算重进、音乐循环接缝与外放层次。记录设备、系统、浏览器或微信版本、构建提交、录屏及帧时间。先定位卡顿、输入丢失或音频恢复问题，再决定优化；CI 上的速度不能拿来推断手机性能。
4. **依据反馈复核当前动作节奏与视觉可读性。** 当前已使用主体 1.5 倍、尾段渐进至 3 倍及主动工具前 0.45 秒保护，不再把这些列为尚未实施的设想。重点观察低力度是否足够精细、缩短等待后能否看清碰撞与敌人预告、抓停/回旋是否来得及点击；继续调整时同时检查瞄准一致性、保存恢复和固定步长结果。
5. **首局成立后，再增加有策略差异的房间变化。** 优先考虑可选宝物路线、能被旧工具利用的新布局、不同风险与落点选择；每项都验证可解性、预告和第二种打法。当前每房免费换工具，局外开局工具主要影响第一房，长期解锁价值仍弱，应通过实际路线差异改善。不要以更多房间、随机数、数值层级或新的界面数量冒充耐玩度。
6. **微信交付按真实依赖推进。** 获得 Creator 环境后按 [WECHAT_RELEASE.md](WECHAT_RELEASE.md) 执行资源导入、正式构建、包体检查、开发者工具和真机，再接真实广告位。源码能够先完成的部分继续推进；缺少外部条件时明确停在哪一层，不虚构产包或收入。

## 6. 接手时最短检查路径

先核对仓库、分支、未提交修改、版本与现有报告对应的源码哈希，阅读本记录及 [APPROVED_SCOPE.md](APPROVED_SCOPE.md)，不要重新从概念阶段开始。本轮目标为 0.2.0 摇杆试玩候选；接手时先确认固定摇杆及当前调参已经进入所测试的网页，再使用对应路线和验收报告。

常规网页构建与检查使用 Node.js 24 或更新版本：

```sh
npm install
npm test
npm run build:web
npm run check:web
python audio-source/verify_score.py
```

`check:web` 需要可启动的 Chromium 和中文字体；本地沙箱若无法启动，使用现有 GitHub Actions 工作流，不把环境失败写成游戏通过。具备官方 Cocos 3.8.8 源码及构建依赖时，再设置 `COCOS_ENGINE_SOURCE` 执行 `npm run check:types` 和 `npm run check:game`。Creator 平台构建另需 `COCOS_CREATOR_388` 与本项目真实 `WECHAT_APP_ID`。

只修改对应源文件并重新生成派生产物；更新实测证据时写清环境、提交与验证边界。最终向用户汇报实际可玩的内容、入口和还未完成的关键环节，不把测试数量当成成品品质。
