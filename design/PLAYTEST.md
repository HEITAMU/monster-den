# 《撞进怪物窝》0.3.0 引导与绕路取宝测试手册

整理日期：2026-11-19（北京时间）。本手册针对 0.3.0 的状态引导、可选钱袋与底部摇杆，区分核心验证、UI 集成和真人观察。本轮 110 项项目测试、严格类型检查、EmptyDevice 与实际 Chromium / WebGL2 已通过，记录绑定运行代码 `cb2fbffc`；[0.3.0 已公开发布](https://heitamu.github.io/monster-den/web/?v=0.3.0)，13 个关键文件 HTTP 核验一致。清单列出要检查的内容，不代表已完成手机验收。

## 操作方式

**按住屏幕下方的摇杆，朝想去的方向推；推得越远，力度越大；松手冲撞。** 不再使用上一版在场景上反向拖拽的操作。想取消时，将摇杆推回中心死区再松手；右侧按钮在冲撞中使用主动工具，重撞拳套持续生效。

摇杆参数由 `core` 的 `JOYSTICK_TUNING` 共用：死区半径 7、满力度行程 75，单位是界面设计单位。死区外的行程重新映射到完整 `0..1` 力度区间，已取消旧版必须超过 10% 才发射的门槛。UI 刚出死区可作约 1% 级别的轻推，精确数值取决于位移和屏幕缩放；死区外 1 个设计单位对应约 1.47%。核心 `shoot()` 本身允许 0 力度，此时仍有小幅移动；**在摇杆中心松手则是取消，不调用发射**。

## 1. 已执行的逻辑检查

在仓库根目录运行：

```bash
node --test tests/core.test.mjs
```

运行环境为Node.js 24或更新版本；测试直接执行纯TypeScript核心，不需要下载测试依赖。

## 2. 完整五房复现条件

为了重现下面的数值，使用新的一局：第一房无开局工具；每次过房选**重撞拳套**；不用救援；每次发射后等待重新可瞄准。路线允许存活敌人留在房里。

逻辑坐标：房间左右为`x=-5..5`，下上为`y=-7..7`。3D表现映射为`(x, height, -y)`。下表目标点指向世界中的位置，传给`shoot()`时应使用“目标点减去当前玩家位置”的方向向量，不可直接把目标点当方向。

当前发射速度范围为 `launchMin=0.55`、`launchMax=12.8`。表中的参考力度已按这组参数重新计算，保留一位小数供人工理解；回归测试使用根据当前位置计算的完整浮点值。真人推杆存在偏差，所以以“能理解并完成路线”作为 UI 验收，不要求手工得到同一坐标、21 发或恰好同一血量。

这条路线最小参考力度为第四房的约 3.7%，在新版摇杆的有效范围内；不要再给整条路线套用旧版 11% 的最低力度。每次出现位置偏差后，应重新看瞄准落点，不机械照抄下一行的百分比。

### 0.2.0 历史动作节奏对照

完整测量、参数、核心源文件哈希和边界保存在 [0.2.0 历史节奏报告](https://github.com/HEITAMU/monster-den/blob/73bc27f5/qa/feel-comparison.json)。旧版基线为 `7aa58e5`；新版测量对应当时 0.2.0 工作树，报告中的源码哈希属于该历史测量。0.3.0 沿用节奏参数，但没有把这份记录改称新版本测量。无碰撞对照使用100×100的空场地和一名不会触及玩家的远处守卫，按120Hz累计 `step()` 输入时间，从发射计到下一次可瞄准，包含敌人动作。

| 力度 | 旧版动作时长 | 0.2.0动作时长 | 旧版位移（模型单位） | 0.2.0位移（模型单位） |
| --- | ---: | ---: | ---: | ---: |
| 11%轻推 | 2.875秒 | 1.250秒 | 2.132 | 1.244 |
| 50%中推 | 3.508秒 | 1.842秒 | 5.275 | 4.777 |
| 100%满推 | 3.917秒 | 2.158秒 | 9.305 | 9.305 |

弱力度的位移缩短来自降低起步速度，满力度距离保持一致；节奏倍率改变的是相同固定物理步的播放进度。低速尾段平滑加快，主动工具前0.45秒保留原速，物理碰撞不跳步。核心的 `state.elapsed` 记录实际传入的活动时间；飞行、敌人和无敌时间仍按名义物理秒推进。

当时自动目标路线的 21 发累计动作为 **28.508 秒**，不含玩家瞄准、犹豫和阅读工具的时间。上述时间是模型中的动作时长，不是脚本的CPU耗时、手机实测帧率或真人手感结论。壁虎和回旋在3%、11%、50%、100%力度下，已分别验证松手0.5秒后仍能使用；实际拇指能否顺手够到工具键，还需下面的手机观察。

| 系统触摸取消 | 瞄准中触发系统取消、切后台或旋转画面 | 不误发射，没有残留摇杆与瞄准点，恢复后能重新控制 |
| 拇指遮挡与可达性 | 左右手分别单手持机、双手持机，观察近底部角色和落点 | 摇杆与工具不会互相遮挡；拇指不遮住关键落点和风险提示；工具能在可用窗口内够到 |
| 双指与工具 | 左拇指瞄准时右手触碰/松开工具或场景，再正常发射并点工具 | 第二根手指不改向、不提前发射、不取消主手指；飞行中工具只生效一次，抓停后可继续瞄准 |
| 地面可读性 | 看预告、出口圈、接触阴影与瞄准点 | 效果在地板上方可见，不被石砖吞掉，也不穿过角色遮挡视线 |
| 方向一致 | 朝八个方向分别推摇杆，再松手发射 | 同向推杆、预览与实际运动一致，斜向无反转；不要求反向拉杆 |
| 物理代理 | 贴近柜子、柱、木栏边缘 | 模型与碰撞形状偏差不造成明显“空气墙” |
| 工具名称与用途卡 | 查看三件工具图标、用途和下一房建议，再经过瞄准/飞行/已用/敌人阶段 | 名称持续保留，状态单列；重撞标自动生效，主动工具只在可用阶段邀请点按 |
| 工具反馈与过期提示 | 抓停后再次发射，进入敌人阶段，最后换房 | 抓停重瞄时敌人不行动；重新发射或敌人阶段清除“守卫暂不行动”，换房清旧房临时提示；回旋只触发一次 |
| 伤害显示与归因 | 普通敌人、窝主、不同房间弩箭分别命中 | 血量、飘字与攻击来源一致；玩家受击，不让攻击者挨打；仅第二房弩箭提示借柜挡箭，其余房提示避开红色箭路 |
| 挡箭提示 | 柜子挡箭、墙挡箭分别观察 | 事件归因正确，不能所有情况都写成柜子挡箭 |
| 飞行中返回 | 发射中切后台，再进入 | 位置、生命、宝物、柜子及敌人状态继续一致 |
| 工具中返回 | 抓停后退出，再进入 | 仍是同回合可重瞄，工具不会凭空多用一次 |
| 过房中返回 | 在选工具面板退出，再进入 | 回到选工具，不能重复加分或丢失过房状态 |
| 失败未结算返回 | 取得钱袋后失败，面板不点按钮，关闭并重进 | 保留已有分数和钱袋累计，恢复终局处理；不能重复发奖，也不能把死亡描述成丢钱 |
| 结算幂等 | 胜利后重开页面、反复进营地 | 金币只入账一次；已结算标记与快照一致 |
| 新局确认 | 有进行中存档时点重新出发 | 清楚表示结束当前局，不能误触覆盖；已解锁工具保留 |
| 坏存档 | 测试环境注入缺少model的局内快照 | 不应被误报为网络/场景加载失败；不会崩溃循环 |

## 5. 广告边界与回调验证

正式广告未配置时，只检查入口布局和不可用反馈，不把它记作真实播放或发奖成功。网页、模拟回调、微信开发者工具、微信真机、正式后台分别记录。

- 完整观看后奖励仅入账一次；重复结束回调不重复奖励。
- 提前关闭、加载失败、播放失败、缺少结束标记，都不发奖。
- 一局救援只能使用一次，恢复后宝物与柜子位置仍一致。
- 广告加载和播放期间，不能通过开新局使旧局奖励写入新局。
- 奖励凭证的runId、placement必须与目标快照匹配。
- 完整观看后突然退出，待领取凭证应在同一局恢复。
- 保存失败时不能显示已经到账；后续恢复不得重复增加金币。
- 广告返回后音频、触摸与界面恢复，不能卡在忙碌状态。

这些回调路径需要平台测试记录和真实广告资格；核心模拟没有验证真实填充与收益。

## 6. 新玩家观察流程

先观察，后提问。首次流程不提前解释柜子、工具或最佳路线，否则不能判断画面本身是否清楚。

1. 给玩家正常入口，只说“玩到你自然想停的时候”。记录加载结束、首次有效推杆与松手、第一房完成及首次停止时间。
2. 记录玩家是否以为推住会持续行走、是否沿用旧版反向拖拽、是否发现回中取消，以及重复无效点击、读不懂的词、看漏的提示和第一次受伤时的反应。
3. 不主动解释清怪条件、钱袋是否必拿或出口如何开启；观察玩家能否根据状态引导、宝箱与钱袋的外观自行理解目标。
4. 一局结束后保持安静，观察是否自发再开。不要先展示未来功能或暗示“后面更好玩”。
5. 结束后问下面的问题，允许负面答案，不替玩家解释。

### 问题

- 你觉得每间房要完成什么才算过关？钱袋和主宝箱有什么不同，出口什么时候会亮？
- 摇杆推向和小兽实际方向是否符合预期？哪个方向或力度最难控制？
- 只想挪一点点时能不能做到？想取消一次操作时会怎么做？
- 握手机时拇指挡住了什么？冲出去之后，能否及时按到工具？
- 哪一次操作最有意思？请指出具体一次；没有也可以说没有。
- 哪一次受伤让你不明白原因？当时你以为会发生什么？
- 柜子移开后改变了什么？看见额外钱袋时，你愿不愿意绕路，为什么？
- 你选的工具做了什么？下次还会选它吗，为什么？
- 从哪一刻开始有些无聊、想等它快点结束，或者不想继续？
- 如果现在再开一局，你想尝试什么？如果不想，再开缺的是什么？
- 哪个物体像能互动但实际上不能，或者能互动但你没有看出来？
- 失败后是否愿意继续，依据是什么？先问玩法，再单独问可选广告入口是否打断体验。

不要只问“好不好玩”。将原话、对应操作录像与解释分开记录，避免把研究者的推测写成玩家意见。

## 7. 设备记录模板

每次真实设备测试至少记录：版本/提交、运行平台、手机型号、系统与微信版本、首次/缓存启动、网络环境、测试路线、录屏、加载错误、触控问题、帧时间异常、前后台恢复、声音、广告环境和结果。

当前测试报告不得仅用“全部通过”代替环境说明。逻辑通过、浏览器通过、微信工具通过、真机通过和真实广告通过是不同证据。
